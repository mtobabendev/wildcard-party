# Gemini native MCP interoperability: stage 1

Public synthetic test endpoint: https://party.wildcarddev.com/api/pennycore-mcp-demo-v1

This endpoint is intentionally public, stateless, and unauthenticated. It has one fixed read-only tool, no imports in its implementation, no DB/network/env access, no private identifiers, no logging of arguments and no write methods. It cannot see the Owner memory bank, even when called with Party cookies or bearer credentials. Never add private functionality to this URL. It is not the private OAuth resource.

Google Connected Apps Platform currently supports MCP 2025-11-25 and earlier Streamable HTTP versions back to 2025-03-26, JSON text tool results, and GET 405 for stateless servers. See https://developers.google.com/connected-apps/mcp/server-optimization. The fixture supports those three versions, initialize, notifications, ping, tools/list and tools/call. No paid inference is made by the endpoint.

In Gemini web, Settings > Connected Apps (or Personal Intelligence > Connected Apps) > Add custom app, enter the URL, then Next. Or use https://gemini.google.com/devmode for developer testing. Google requires eligible US adult personal accounts, English and Keep Activity enabled. Do not change activity settings without Owner consent. See https://support.google.com/gemini/answer/17209137 and https://support.google.com/gemini/answer/13594961. With Keep Activity on, Google may retain and use chats for model improvement including human review. Test only with fictional data.

In a new Gemini chat select the connected app with @ and request: "Call get_demo_megaseed using the PennyCore demo app. Report the readiness code, selected telescope, and whether this is real or synthetic data." Expected output: LANTERN-ORBIT-47, copper telescope, synthetic only. Inspect the actual tool invocation in Developer Mode when available; an assistant acknowledgment alone is not proof.

Stage 2, separate Owner Gate: test a separate authenticated synthetic endpoint with OAuth authorization code + S256 PKCE, exact registered Google callback, issuer/resource audience and scope binding, short-lived opaque tokens, revocation, single-use authorization codes, CSRF-safe explicit consent using existing verified Party Owner session, server-side storage, and negative tests. Do not accept Party browser cookies as MCP bearer authority. No dynamic registration granting access without consent. Google discovery and callback details: https://developers.google.com/connected-apps/mcp/oauth. Verify provider eligibility and actual registered callback before implementing the authorization flow. Do not connect real memory until OAuth and revocation are verified, the Owner chooses which records may be shared, and the data-retention tradeoff is accepted. Use a separate least-privilege data access path limited to explicitly selected records; no raw journal dump, global search, state writes or paid fallback. A future write tool requires separate authorization and explicit per-capture review. No actual private data may be used in stage 1.
