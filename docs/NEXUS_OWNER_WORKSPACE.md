# Nexus owner workspace / continuity capture

The dedicated /nexus.html entry is built separately from the Party application and its public concierge script. It reuses Party's HttpOnly Secure session and the server-verified PENNYCORE_OWNER_ACCOUNT_ID. It never accepts a client-supplied identity. No model proxy, provider credentials, automatic export, or shared-memory injection. Native provider sessions require their own sign-in. Grok native access is distinct from paid API integration.

The existing six approved engineering records are read through the existing Owner Gate. Personal continuity captures are a separate append-only store. Each capture is encrypted with AES-256-GCM and a random nonce, bound to account and request ID by authenticated associated data. The encryption key is server-managed, not end-to-end encryption. No personal captures enter PennyCore engineering records or model prompts automatically. Explicit selected-packet copy is the only cross-provider handoff in this release. The user must review what is sent to a provider. Never store secrets.

Activation is deliberately separate: create an isolated Neon database and a non-owner runtime role with only SELECT/INSERT and identity sequence usage, apply db/nexus/001_owner_memory.sql as migration owner, configure NEXUS_MEMORY_DATABASE_URL and a generated 32-byte base64 NEXUS_MEMORY_KEY as server-only sensitive Production environment variables, and enable NEXUS_MEMORY_ENABLED=1 only after Owner approval. Do not copy these values to Preview, browser code, Git or chat. Preserve an encrypted recovery copy of the key in an Owner-controlled location; key loss means records cannot be recovered. No automatic DDL, data migration, or production writes on build. Test the database and grants with synthetic captures before enabling real data. No automatic deletion or key rotation in this release; design those separately. Native-provider history synchronization requires supported export or explicit capture integrations and separate consent, not session scraping or access-token reuse.

MegaSeed v1 import accepts exactly five string fields (optionally one JSON fence), rejects duplicate keys, validates size and known secret patterns locally and on the server. Source is Owner-selected attribution, not independently verified provider identity. Dedup uses account-scoped HMAC-SHA-256 over canonical trimmed five fields, not source/request ID. One encrypted canonical packet plus append-only source receipts; receipt creation and canonical insertion are atomic via an invoker-rights function. Runtime requires SELECT/INSERT on both tables, sequence USAGE and function EXECUTE, not ownership. Source labels, timestamps and keyed digests are visible database metadata. Different facts or summaries are separate packets, not silently merged. Restore copies exact JSON and the restore command; no automatic provider transfer. Fresh schema only; if any earlier database exists, stop for migration review.

## Mark II workbench

After Owner authentication, load the newest page automatically. Search and source filters operate on decrypted records already in browser memory; search strings are never transmitted or stored. Load up to five older pages per explicit action, with pagination preserved; no claim to search unloaded data. Suggestions use deterministic title-weighted keyword matching, not inference or persisted categories. Select at most six records and review an exact restore preview (48 KB maximum), including source attribution and timestamps outside the five-field JSON. Copy or copy-and-open a native provider only after explicit share review. Nothing is included in provider URLs or automatically submitted. Paste events and explicit clipboard reads validate and populate a single draft; invalid input blocks save until resolved or cleared. No automatic clipboard access, persistent local browser storage, schema changes, new credentials or model calls. Sign-out clears workspace state. Browser clipboard and pop-up restrictions can require manual copy/open. Direct provider MCP/OAuth integration is a separate security boundary and not part of this release.

See [Gemini native MCP interoperability](PENNYCORE_GEMINI_MCP.md) for the separate public synthetic compatibility fixture. It has no access to this workspace or private storage.
