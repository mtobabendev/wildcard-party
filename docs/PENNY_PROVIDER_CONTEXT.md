# PC.3A — Provider-neutral owner consultation

Owner Gate adds an explicitly authorized, one-turn project consultation. Each request reads the six allowlisted latest records from the existing PC.2B server gateway and sends the identical bounded context packet plus a question to the selected provider. No automatic provider fallback. No personal notes, account history, human messages, project-memory write credentials, arbitrary record queries or operational tools. Replies exist only in the current UI, not the database. Provider retention policies still apply; store:false is requested where supported, not a zero-retention guarantee.

The route is production-only and requires the verified owner session, existing read credential, same-origin POST and explicit per-request consent. OpenAI uses current Party configuration. Gemini and Grok require their existing provider-specific API key and model configuration; their owner-only route does not enable guest external-provider access. No provider calls happen in preview. Tests use synthetic fixtures only. Context over 16,000 characters fails closed rather than truncating records.

Before merge: confirm CI and preview access boundaries. Before external-provider activation: verify current provider contracts and explicitly approve configuration. After production approval: owner must load six records successfully, then send a synthetic project question to OpenAI. Verify response and ordinary-account denial; only then mark OpenAI project consultation live. Gemini and Grok remain unverified until configured and individually tested. Cross-provider saved conversation, controlled memory updates, and agent/ChatGPT connector access are separate later stages.
