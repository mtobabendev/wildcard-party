# Penny Core M.3A
Private, opt-in AI conversation and user-edited notes inside Messenger. Existing guest Ask Penny and human COMMS stay separate. State is scoped exclusively by the authenticated Party session; there is no operator role, tool access or automatic memory extraction. No cross-origin cookies or shared credentials. The existing Neon project is the online store; PennyKey local-first synchronization and encrypted backups remain future work.

The new table is created lazily on first authenticated request, following the existing Party schema pattern. Preview uses its own database. Do not copy preview accounts or state to production. State writes are revision-checked to prevent silent cross-device overwrites. Keep the latest 40 messages, supply at most 10 recent messages and 6000 characters of explicit notes within a 12000-character model context. Clearing history affects active state only, not provider or database retention. Notes can be cleared by saving an empty value. No raw messages or secrets in Git.

Verification before merge: run node --test test/penny-core-state.test.js and npm run build; test two accounts in preview, cross-account isolation, save/reload, chat/reload, stale revision conflict, clearing, guest 401, no changes to public Ask Penny or human messaging. No production migration until approved merge. Rate limiter is inherited and instance-local, not a distributed quota. Model request is nonstreaming and must complete before a turn is persisted.
